# Полное описание функционала — сайт и Telegram-бот «Альбина»

Документ описывает **что делает система целиком**: публичный сайт, админку,
бэкенд-API и Telegram-бота. Актуальное состояние — в разделе
[«Что работает, что осталось»](#7-статус-что-работает-что-осталось).

**Сайт живёт на проде:** https://24albinadisigner.ru/

---

## 1. Обзор

Сайт-визитка стилиста Альбины: она подбирает образы (капсула гардероба,
совместный шопинг, шоп-тур). Сайт рассказывает об услугах, собирает заявки и
выдаёт бесплатный лид-магнит (PDF-гайд по самостоятельному разбору гардероба)
через Telegram-бота. Единственный способ связаться с Альбиной с сайта — Telegram
(по решению заказчика телефон и Instagram убраны из публичных контактов).

**Технологии:** React + Vite (фронтенд), Django 6 + Django REST Framework
(бэкенд), aiogram (Telegram-бот), PostgreSQL (БД). Локально — Docker Postgres;
боевой сервер — VPS в Санкт-Петербурге (152-ФЗ), Nginx проксирует `/api/` и
`/admin/` на gunicorn, отдаёт статику фронтенда и медиа напрямую.

**Аудитория:** женщины 27–55 лет. Офлайн-услуги — Москва и Саратов; шоп-тур —
без географических ограничений.

## 2. Карта сайта (публичная часть)

SPA на React Router, весь контент — из Django API (`GET /api/...`), ничего не
захардкожено.

### Шапка / подвал (на всех страницах)
- Логотип `albina.` → на главную. Навигация: **Услуги**, **Блог**, **О мне**,
  **Написать** (последняя — скролл к форме заявки).
- Подвал: те же ссылки + **единственные контакты** — «Написать в Telegram»
  (бот) и «Канал в Telegram».

### Главная (`/`)
Hero → бегущий тикер → «Процесс, а не витрина» (4 фото-плейсхолдера) → 3
карточки услуг (из API) → лид-магнит (тёмный CTA с реальной deep-link кнопкой
в бота).

### Услуги (`/services`) и детальная страница (`/services/<slug>`)
Список из 3 услуг с карточками (из API); на детальной — шаги «как это
работает», примеры, отзыв, «кому подойдёт»/«что получишь», персональный CTA.
**Кнопки записи** («Заказать капсулу» и т.п.) не ведут на `#` — они
прокручивают к форме заявки внизу страницы и **сразу подставляют нужную
услугу** в выпадающий список.

### Блог (`/blog`) и запись (`/blog/<slug>`)
Featured-пост + сетка записей (из API, с пагинацией DRF). **«Показать ещё»
реально подгружает следующую страницу** и исчезает, когда записей больше нет.
Каждая карточка кликабельна → полная запись со всем текстом. Записи либо
заведены вручную в Django-admin, либо **автоматически пришли из Telegram-канала
Альбины** через бота (см. раздел 5).

### О мне (`/about`)
Био и цитата — из `SiteProfile` через API.

### Форма заявки (на каждой странице, `#lead-form`, перед подвалом)
Имя, телефон, услуга (необязательно, можно предвыбрать кнопкой на странице
услуги), комментарий. Отправка → `POST /api/leads/` → запись в БД → **сразу же
уведомление Альбине в Telegram** (см. раздел 5, сценарий 2). Проверено
end-to-end на проде.

### 404 (`*`)
«Страница потерялась», кнопка «На главную».

## 3. Админка

Два разных места, не путать:

### 3.1. Django-admin (`/admin/`) — где Альбина реально работает
Профиль сайта (singleton: био, Telegram-ссылки, тексты и PDF лид-магнита,
секрет для бота), услуги + отзывы, записи блога (черновик/опубликовано, статус
меняется списком), заявки (статус, фильтры, поиск), подписчики Telegram.

### 3.2. Фронтовый дашборд-макет (`/admin` на сайте)
Визуальный прототип кастомной админки с демо-данными — не подключён к реальным
данным, кнопки не работают. Показывает, как могла бы выглядеть более удобная
панель поверх того же API, если это понадобится в будущем.

## 4. Бэкенд-API (Django REST Framework)

Префикс `/api/`. Чтение — публично, `POST /api/leads/` — публично, остальное
по заявкам — только для персонала.

| Метод | Эндпоинт | Назначение | Доступ |
|-------|----------|-----------|--------|
| GET | `/api/health/` | проверка БД | публично |
| GET | `/api/profile/` | профиль сайта (био, Telegram-ссылки, лид-магнит) | публично |
| GET | `/api/services/` | список услуг | публично |
| GET | `/api/services/<slug>/` | услуга + вложенные отзывы | публично |
| GET | `/api/reviews/` | все опубликованные отзывы | публично |
| GET | `/api/posts/` | опубликованные записи блога (пагинация) | публично |
| GET | `/api/posts/<slug>/` | запись блога с полным текстом | публично |
| POST | `/api/leads/` | создать заявку с сайта (по slug услуги) | публично |
| GET | `/api/leads/` | список/просмотр заявок | только staff |

### Модели данных
- **SiteProfile** (core) — singleton: био, `telegram_channel_url`/
  `telegram_bot_url`, `lead_magnet_*` (включая файл и deep-link параметр),
  `owner_telegram_chat_id`/`admin_claim_secret` — бутстрап админа бота.
- **Service** / **Review** (services).
- **BlogPost** (blog) — включая `telegram_message_id` для синхронизации с
  каналом (создание и правка без дублей).
- **Lead** / **TelegramSubscriber** (leads). При создании `Lead` срабатывает
  сигнал → прямой HTTPS-вызов Telegram Bot API (не зависит от того, жив ли
  процесс бота).

Наполнение контентом — `python manage.py seed_demo_data` (идемпотентно,
`update_or_create`).

## 5. Telegram-бот (@AlbinaDesigner_bot) — реализован и работает на проде

Код — `webapp/backend/core/telegram_bot/` + `manage.py run_bot`. Использует
Django ORM в standalone-режиме (тот же venv/БД, что и сайт), long polling.

### Сценарий 1 — выдача лид-магнита
Кнопки «Подписаться в Telegram» на сайте ведут на
`https://t.me/AlbinaDesigner_bot?start=wardrobe_guide`. Бот присылает PDF-гайд
и сохраняет подписчика. Обычный `/start` без параметра — приветствие с
кнопками «Получить гайд» и «Канал Альбины».

### Сценарий 2 — уведомление о заявках
Новая заявка на сайте → Django-сигнал → `sendMessage` в Telegram Альбине
(имя, телефон, услуга, комментарий). Работает независимо от бота — это прямой
HTTP-вызов из Django.

**Бутстрап админа** (Telegram не даёт боту написать первым): Альбина один раз
пишет боту `/claim_admin <секрет>` — секрет сгенерирован и лежит в Django-admin
(«Профиль сайта» → «Бот: админ-доступ»). После этого `owner_telegram_chat_id`
заполняется автоматически, и заявки начинают приходить ей в личку. Дальше в
боте доступна команда `/leads` — последние 5 заявок по запросу.

### Сценарий 3 — зеркалирование канала в блог
Бот подключён администратором к каналу **@nadevai_24**. Каждый пост в канале
(текст/фото+подпись) автоматически создаёт запись в блоге (заголовок — первая
строка, остальное — текст и анонс, обложка — фото поста, если есть). Правка
поста в канале обновляет ту же запись блога, а не создаёт дубликат
(`telegram_message_id`).

### Не сделано
**Рассылка подписчикам** — формат не определён заказчиком, не проектировалась
(см. Диз-док).

### Важный инфраструктурный нюанс
DNS-ответ `api.telegram.org` → `149.154.166.110` **блокируется на уровне
TLS/SNI** у хостинг-провайдера/апстрима сервера (сам факт использования
Telegram не заблокирован — TCP/ping до этого IP проходят, а вот TLS-рукопожатие
с SNI `api.telegram.org` до него — нет). Рабочий IP того же пула Telegram
(`149.154.167.220`) не блокируется. Решение — на сервере в `/etc/hosts`
прописана строка `149.154.167.220 api.telegram.org`. Это **не обход блокировки
через VPN/прокси**, а выбор другого легитимного адреса того же сервиса.
Хрупкое место: если провайдер обновит `/etc/hosts` (файл управляется Ansible
при первичной настройке хостером) или Telegram перестанет отвечать с этого IP —
бот и уведомления о заявках перестанут работать с таймаутом на стороне сервера.
Если это случится — переподобрать рабочий IP тем же способом (`openssl s_client
-connect <ip>:443 -servername api.telegram.org`) и обновить `/etc/hosts`.

## 6. Дизайн-система и анимации

- **Палитра:** камел / айвори / эспрессо + лаковый красный акцент + масляно-
  жёлтый вторичный.
- **Шрифты:** Unbounded (заголовки), Golos Text (текст), JetBrains Mono
  (подписи/цены/метки). Самохостинг.
- **Фирменный мотив:** «рамка зеркала примерочной» вокруг фото — везде
  плейсхолдеры (реальных фото пока нет, см. project memory про непроверенные
  архивы фото).
- **Анимации:** появление блоков при скролле (с fallback-таймером, чтобы
  контент не застревал невидимым), бегущий тикер, hover-эффекты. Уважают
  `prefers-reduced-motion`.

## 7. Статус: что работает, что осталось

### ✅ Работает и проверено (локально + на проде)
- Вся навигация, маршрутизация, редиректы, 404.
- Все страницы получают контент из Django API, не из захардкоженных данных.
- Форма заявки — от клика до записи в БД до уведомления в Telegram, проверено
  на реальном домене.
- Кнопки записи на услугах предвыбирают услугу в форме.
- Блог: пагинация «Показать ещё», отдельные страницы записей.
- Telegram-бот: выдача гайда, бутстрап админа, `/leads`, зеркалирование канала
  в блог (включая правки без дублей) — всё развёрнуто и работает на проде.
- Только Telegram как способ связи (шапка/подвал).
- Django-admin: полное управление контентом.
- Все анимации, hover-эффекты, консоль без ошибок на всех страницах и обеих
  ширинах экрана.

### ⚠️ Осталось / известные ограничения
1. **Фото — везде плейсхолдеры.** Реальных фото Альбины с подтверждёнными
   правами пока нет (см. project memory).
2. **Рассылка подписчикам** не спроектирована — заказчик не определил формат.
3. **Фронтовый `/admin`** остаётся визуальным макетом с демо-данными, не
   подключён к реальному API — управление контентом идёт через Django-admin.
4. **Отдельный deploy-пользователь** не создан, всё работает от `root` — можно
   сделать отдельно, не блокирует текущую работу сайта.
5. **`/etc/hosts`-костыль для Telegram API** (см. раздел 5) — хрупкое место,
   отслеживать при проблемах с ботом/уведомлениями.

### 📝 Замечания к контенту (на решение заказчика)
- **Смысловая нестыковка:** в тексте «О мне» упомянуты «персональные разборы
  гардероба» в портфолио — спорит с новым позиционированием (разбор гардероба
  теперь бесплатный self-service PDF, Альбина отмечала, что не любит эту
  работу). Стоит согласовать формулировку.
- **Разный тон:** «О мне» — от третьего лица, весь остальной сайт — от первого
  лица на «ты». Для единого голоса бренда стоит переписать «О мне».
